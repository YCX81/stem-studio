# Stem Studio 设备音频协议 v1

## 产品边界

v1 采用“桌面六轨分离与混音，设备负责控制和立体声播放”：

1. 桌面沿同一采样时钟混合二/四/六轨。
2. 桌面把混合后的 PCM16LE 立体声音频通过局域网发送到黄山派。
3. 黄山派的旋钮、按键或触屏把各轨增益命令发回桌面。
4. 桌面在 20 ms 斜坡内应用增益，后续 PCM 包立即体现新混音结果。

这种方式在 44.1 kHz 时只需 `1.4112 Mbit/s` PCM 有效载荷；若把六条立体声
stem 全部发给设备端混音，有效载荷会增至 `8.4672 Mbit/s`，还会增加六轨时钟对齐、
丢包恢复和设备内存压力。设备端六轨混音保留为后续协议版本，不作为 v1 无卡顿验收前提。

## 传输约束

- UDP 数据报最多 1400 字节，避免在常规 1500 MTU 以太网/Wi-Fi 网络发生 IP 分片。
- PCM 仅支持双声道、16 位、小端、44.1 kHz 或 48 kHz。
- 每个音频包携带会话 ID、连续序号和绝对播放帧；切换会话时设备必须清空旧抖动缓冲。
- CRC32 使用 IEEE 多项式 `0xedb88320`；计算时把包内 CRC 字段视为 0，覆盖其余整个数据报。
- v1 是未压缩 PCM，成功收到的样本位级无损；UDP 丢包仍可能造成缺帧，因此在完成抖动缓冲、
  丢包统计及真实设备长播验收前，不能宣称网络链路“完全无卡顿”。
- 编码 API 由调用方提供输出缓冲，不在实时音频线程中分配内存。

建议桌面每包发送约 5 ms 音频：44.1 kHz 使用 220 或 221 帧，48 kHz 使用 240 帧。
黄山派首版应准备至少 100–250 ms 的立体声抖动缓冲，并以 I2S/DAC 播放时钟为主时钟。

## 公共头

所有多字节整数均为小端。包开头四字节固定为 ASCII `SSNP`。

| 偏移 | 大小 | 字段 | 值 |
|---:|---:|---|---|
| 0 | 4 | magic | `SSNP` |
| 4 | 1 | version | `1` |
| 5 | 1 | type | 音频 `1`，控制 `2` |
| 6 | 2 | header/packet bytes | 按包类型解释 |

## 音频包，type=1

固定头长 40 字节，总包长不超过 1400 字节。

| 偏移 | 大小 | 字段 | 说明 |
|---:|---:|---|---|
| 8 | 4 | session_id | 桌面每次建立新播放会话时改变 |
| 12 | 4 | sequence | 每个音频包递增，允许 uint32 回绕 |
| 16 | 8 | presentation_frame | 本包首帧在会话采样时钟中的绝对位置 |
| 24 | 4 | sample_rate | `44100` 或 `48000` |
| 28 | 2 | frame_count | 本包立体声帧数 |
| 30 | 1 | channels | 固定 `2` |
| 31 | 1 | sample_format | PCM16LE 固定 `1` |
| 32 | 2 | payload_bytes | 必须等于 `frame_count × 2 × 2` |
| 34 | 2 | reserved | 固定 `0` |
| 36 | 4 | crc32 | 整包 CRC32，计算时本字段视为 0 |
| 40 | 可变 | PCM payload | L、R 交错 PCM16LE |

设备必须拒绝 magic、版本、类型、长度、几何或 CRC 不符的包；不能把损坏数据送进 I2S。
序号缺口、重复、迟到、会话切换和抖动缓冲水位必须独立计数并反馈到桌面状态页。

## 混音控制包，type=2

控制包固定 48 字节，采用定长结构，便于 ESP-IDF/Arduino 固件无堆解析。

| 偏移 | 大小 | 字段 | 说明 |
|---:|---:|---|---|
| 8 | 4 | session_id | 必须匹配当前桌面播放会话 |
| 12 | 4 | sequence | 控制命令递增序号；重复或旧命令应忽略 |
| 16 | 8 | issued_at_ms | 设备单调时钟毫秒值，用于延迟诊断 |
| 24 | 1 | valid_stem_mask | 下表所列有效轨位 |
| 25 | 3 | reserved | 固定 `0` |
| 28 | 14 | gains_q15 | 7 个 uint16 增益，`0` 静音，`32768` 为 1.0 |
| 42 | 2 | reserved | 固定 `0` |
| 44 | 4 | crc32 | 整包 CRC32，计算时本字段视为 0 |

轨位顺序与掩码：

| bit / 数组下标 | 轨道 |
|---:|---|
| 0 | vocals |
| 1 | instrumental |
| 2 | drums |
| 3 | bass |
| 4 | other |
| 5 | guitar |
| 6 | piano |

六轨配置的有效掩码为 `0b01111101`；二轨配置使用 vocals 与 instrumental。
桌面收到命令后只应用掩码内轨位，并继续使用现有 20 ms 增益斜坡。

## 扩展板最低职责

- 稳定的 2.4/5 GHz 局域网连接与可观测 RSSI；网络栈不得运行在 I2S 实时回调中。
- 足够容纳至少 250 ms PCM16 立体声的 RAM/PSRAM 环形缓冲。
- 独立 I2S DAC 或高质量音频 codec、低噪声电源、耳放/线路输出；若驱动扬声器则增加功放与保护。
- 本地播放时钟、抖动缓冲水位、丢包/迟到/CRC 错误和重缓冲计数。
- 六轨旋钮/编码器、静音键及显示；控制命令必须带序号并可在断线后恢复最后确认值。
- 看门狗、掉线重连和安全静音，不能在缓冲耗尽时循环播放旧 PCM。

## 完成条件

协议编解码测试通过只证明线格式正确。产品完成还要求 Windows 异步发送队列、设备端接收/抖动缓冲、
控制回传、状态可视化，以及在目标板上不少于 10 分钟的零缺包/零欠载实测。
